# Task Digest

读取 `~/.zcode/v2/tasks-index.sqlite` 与 `~/.zcode/cli/db/db.sqlite`（均只读），把 ZCode 的历史任务转成可读摘要。

## 工具

| 工具 | 用途 |
|---|---|
| `digest_snapshot` | 一次拿全：总量指标 + 每日 token 趋势 + 任务列表。参数 `range`（today/3d/7d/30d/all）、`limit`、`workspace` |
| `digest_task_detail` | 单个任务的完整画像：耗时、token、工具明细、待办清单、每日用量。参数 `task_id` |
| `digest_workspaces` | 按工作区聚合任务数、token、工具调用、最近使用时间 |
| `open_digest` | 打开可视化面板（侧栏），支持范围切换与任务下钻 |

## 写摘要的输出格式

拿到数据后按这个骨架组织，不要罗列原始 JSON：

```
## 概览
<范围内>共 N 个任务，消耗 X token、Y 次工具调用，成功率 Z%。

## 值得注意的
- 最重的任务：<标题>（<工作区>，X token / Y 次工具 / Zh）
- 未完成的待办：<任务标题> 还剩 A/B 项
- 异常：<出错或中断的任务及其可能原因>

## 按工作区
<工作区> — N 个任务 / X token / Y 次调用
```

## 规则

- 只报数据里有的，不推测未发生的进度。
- token 单位统一用 B（十亿）/ M（百万），保留两位小数。
- 成功率 = `toolOk / toolCalls`，不是任务成功率，措辞要说清是「工具调用成功率」。
- 任务标题已脱敏（密钥、token 被替换为 `***`），引用时保持原样，不要尝试还原。
- 数据是某一时刻的快照，写明生成时间。
- 用户只要数字时，直接给表，不套上面的骨架。
